# Round 07 — city visuals brief (Vintage Etching upgrade)

**Objective.** Make the playable prototype look appealing as a 1925 interwar etched
city: varied houses with **pitched roofs as the norm** (not uniform "brick boxes"), a
set of **distinct landmarks** (sports ground, town hall, church, gardens, and more),
and a richer Vintage Etching treatment — all behind the existing developer skin
boundary, without touching the rules, the graph, station positions or the game loop.

Work is ordered **best bang-for-buck first**, so the game gets visibly better at every
stop and can be handed off mid-way. A fresh session (e.g. a "Flash" model) with no
memory of prior conversation should be able to execute this file top to bottom.

## Fixed inputs (do not vary)

| Input | Path / value | Why fixed |
| --- | --- | --- |
| Map data | `maps/prototype-96-seed-42.json`, regenerated by `@x-yard/map-generator` | Station positions, blocks, streets and the graph are the board; changing them changes the game |
| Rules / graph | `packages/game-core` | Untouched. Zero-dependency, deterministic engine |
| Projection | 2:1 isometric in `apps/web/src/prototype/projection.ts` | The whole overlay (stations, routes, tokens, ghost) is projected against it |
| Skin boundary | `apps/web/src/prototype/skins/index.ts` + `MapStage` | `vintage` is default; `basic` is the fallback and must stay |
| Transit colour | the network is the **only** saturated layer (`VINTAGE.route` in `apps/web/src/lab/rts/rtsTheme.ts`) | Core Vintage Etching directive |
| Era | **1925, interwar** ([decision 0023](../decisions/0023-era-1925.md)) | No modern props (neon, AC, billboards, antennas); motor traffic stays sparse |

## The delta — ordered by bang-for-buck

Do them in this order. Each item is independently shippable.

1. **Sloping roofs + house types** (highest ROI). In `apps/web/src/prototype/city.ts`,
   add a `roof`/`type` field to `Building`, assigned deterministically from
   `hash(blockId + row + col) ^ map.seed`, with **pitched roofs the majority**:
   terrace (gable), townhouse (gable/hip), cottage (steep gable), mansion (hip),
   tenement (flat + parapet), warehouse/factory (sawtooth), shop (flat + awning).
   In `apps/web/src/prototype/CanvasCity.tsx`, replace the single `gable` boolean in
   `drawBuilding()` with a roof-shape renderer: gable, hipped, mansard, flat + parapet,
   sawtooth, each with a ridge line, dormers and chimney pots where the type calls for
   them. Keep all new detail behind the existing `detail` flag so map zoom stays cheap.
2. **Wall material & tint variety.** Vary `VINTAGE.walls` per building (render, stone,
   brick, timber tints) by the same hash, so nothing reads as a uniform "brick box".
3. **Paper grain + ink outline + denser hatching.** In `CanvasCity.tsx`, add a
   paper-grain `createPattern` tile for the ground/blocks (copy the existing
   `hatchPattern` pattern as the model), strengthen `VINTAGE.blockEdge` / `shadow`, and
   raise hatching density on shadow faces. Goal: read as an etching, not flat sepia.
4. **Richer existing landmark silhouettes.** In `CanvasCity.tsx` `drawLandmark()`, give
   the four existing kinds distinct era-plausible silhouettes (cathedral spire, station
   train-shed/clock, market hall roof, square fountain/obelisk). Pure renderer; no data
   change.
5. **New landmark kinds.** Widen `LandmarkModel['kind']` in
   `packages/map-generator/src/types.ts` with a period set — `sportsGround` (the 1920s
   "stadium"), `townHall` (city hall, clock tower + portico), `church` (nave + steeple +
   spire), `gardens` (named park with bandstand, distinct from anonymous `park` blocks),
   plus `hospital`, `museum`, `university`, `theatre`, `gasworks`. In `grid.ts`, select a
   seeded, varied set (keep `cathedral` + `station` as anchors); any count/ratio is a
   `PROVISIONAL_` constant. Regenerate committed fixtures by running the map-generator
   tests (they rewrite `maps/*.json`). Render each kind distinctly in `drawLandmark()`.
6. **Row terraces.** In `city.ts` `buildingsForBlock()`, group cells into terraced runs
   with shared party walls and one continuous roofline, instead of isolated boxes. The
   deeper fix for "similar houses".
7. **Period street furniture.** Gas lamps, a hansom cab/omnibus, cast-iron railings,
   bollards. Must obey the ambient-actor rule (tiny, desaturated, unringed, never on a
   station). Optional.
8. **River + bridges.** New generator geometry (a river crossing the lattice + 2–3
   bridges with piers) in `grid.ts`, rendered in `CanvasCity.tsx`, fixtures regenerated.
   Highest cost of the "real city" items; do last.
9. **(Deferred) Pre-rendered sprites / AI textures.** Later, behind the same skin
   boundary; never before the vector city is finished. See "External assets" below.

## External assets (opt-in, phased later)

Approved as a *later* phase, gated on director sign-off for anything paid. Cheapest
first: AI image models (DALL·E / gpt-image-1, Stability SDXL, Replicate) for etching
reference plates and seamless paper/brick/slate/cobblestone textures baked into small
`createPattern` tiles; Blender (free, Python batch-render isometric) or MagicaVoxel
(free voxel) for pre-rendered building/landmark sprites, packed with TexturePacker /
Shoebox. Assets live in `apps/web` and are loaded by the renderer only. They **never**
enter `game-core` (zero deps, deterministic) or `map-generator` (pure — it emits data,
not pixels). Seeded geometry stays deterministic; textures only change how it is painted.

## Constraints (restated, do not discover)

- `pnpm test` from the repository root must pass before the task is complete.
- `packages/game-core` keeps `"dependencies": {}`; it is **not** touched by this round.
- TypeScript strict mode stays on; fix code, never weaken `tsconfig.base.json`.
- **Landmarks are data, not drawing.** `map-generator/src/types.ts` states "the model is
  authority, the renderer is a view" and "no drawing code may invent geometry." New
  landmark kinds must be added to `LandmarkModel['kind']`; the renderer only draws
  declared kinds. Building variety, by contrast, is *seeded presentation decoration* in
  the client and must not enter `GeneratedMap`.
- **Deterministic.** Building/roof choices are seeded by hash ^ map seed (the existing
  mechanism); never `Math.random()` at render time or the city reshuffles each frame.
  `map-generator` is pure and deterministic; changing `grid.ts` requires regenerating the
  committed `maps/*.json` fixtures (the generator tests already rewrite + assert equality).
- **`PROVISIONAL_`.** Any new unratified number (landmark count, park ratio, etc.) is a
  named `PROVISIONAL_`-prefixed constant, one per number.
- **Ambient actors are a legibility risk.** Furniture/pedestrians must be tiny,
  desaturated, unringed and never overlap a station; when in doubt, omit.
- **The network stays the only saturated colour** in the Vintage skin.
- **Do not rename modes** (taxi/bus/underground/special). Internal names are fixed
  ([decision 0019](../decisions/0019-1907-era-rules.md)); presentation labels are
  out of scope.
