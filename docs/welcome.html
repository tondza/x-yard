X-Yard

PROJECT INTRO & GETTING STARTED — FOR CONTRIBUTORS

Welcome. X-Yard is a browser game of hidden movement and deduction — several Fugitives move secretly across a city's transit network while a team of Agents hunts them using only ticket trails and scheduled sightings. This page gets you from "what is this?" to a running game and a first pull request, assuming an AI agent is doing the mechanical work under your direction.

One human + bots today TypeScript monorepo Pure rules engine Codespaces-ready

1 · In one minute

The idea

Fugitives ride taxi, bus, underground and special links. Agents see the ticket used but not the destination — except at a scheduled Appearance. Capture is occupying the exact same station.

The code

Five small packages. The rules engine (game-core) is pure and deterministic — a game is replayable from a seed and an event log. Everything else renders it or carries it over the wire.

2 · How we work together

Maintainer

  • Owns main, merges pull requests.
  • Writes PROJECT_LOG.md and docs/status.md.
  • Approves any game-number or vocabulary change.

Contributor (you)

  • Works on a batch-NN-<slug> branch.
  • Opens a pull request; never pushes to main.
  • Runs the checks before submitting.
1
Pick a batch from the backlog (or agree one).
2
Branch batch-NN-<slug> and read that batch's brief.
3
Change only the files in the brief's scope lock; run the checks.
4
Open a PR — CI runs the gate and the scope check automatically.
5
The maintainer reviews and merges, and writes the log entry.

3 · Start: create your Codespace

1
Accept the collaborator invite from the maintainer.
2
Open github.com/tondza/x-yard.
3
Click Code ▾ → Codespaces → Create codespace on main.
4
Wait for the dev container to install Node 22 + pnpm 12.3.4 and run pnpm install.
5
The editor opens. In its terminal, confirm:
node --version   # ≥ 20.19
pnpm --version  # 12.3.4

4 · The commands you'll use

pnpm install                       # first install (runs automatically in Codespaces)
pnpm test                          # the gate — full suite, every workspace
pnpm typecheck                     # tsc --noEmit
pnpm build                         # production build
pnpm check:docs                    # links + documented counts
pnpm --filter @x-yard/web dev      # run the game (forward port 5173)
git checkout -b batch-09-river-bridges   # new batch branch
git add -A && git commit -m "..."        # commit
git push -u origin batch-09-river-bridges # push, then open a PR on GitHub

The running game is at https://<codespace>-5173.app.github.dev/ once port 5173 is forwarded.

5 · Your AI agent: prompt examples

Whichever agent you use (Claude Code, Deepseek Harness, Cline, Hermes), give it this first prompt. It reads AGENTS.md automatically, so the project's rules come along for free.

Opening prompt

Read AGENTS.md, then CONTRIBUTING.md. I am a contributor, not the
maintainer. Summarise the three non-negotiables and the batch protocol
in a few lines, then tell me the next command to run.

Starting a batch

Read AGENTS.md, then docs/briefs/batch-09-river-bridges.md.
Work on branch batch-09-river-bridges. Touch only the paths in the
brief's scope lock. Run `pnpm verify && pnpm test` before finishing.
Do not edit PROJECT_LOG.md or docs/status.md. Do not run `git push`.
Standing rule: the agent never runs git push and never edits PROJECT_LOG.md or docs/status.md — you push, the maintainer merges.
